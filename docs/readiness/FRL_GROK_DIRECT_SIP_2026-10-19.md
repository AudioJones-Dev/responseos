## Feasibility and current evidence

Official [Direct SIP](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech/sip) documents a Telnyx route, signed incoming events, a call-ID WebSocket and a hangup endpoint. It bridges caller media into the session. This establishes protocol feasibility, not compatibility with the existing consent gate. The guide does not establish pre-consent media isolation, Telnyx-to-xAI exact identity preservation or authenticated terminal-disconnection evidence. Its generic TLS URI and Telnyx-specific port example also need an explicit verified transport configuration before routing.

The [voice guide](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech) documents the versioned model grok-voice-3.0, query-based model selection, configurable tools and opt-in resumption. The offline preview combines call_id with that exact model. Successful negotiation on an actual SIP session remains unverified. No alias fallback is permitted. A response cancel, socket close or disabled VAD is not a media-isolation or PSTN-disconnection guarantee.

Recommendation: persistent outbound WebSocket worker with explicit ownership, heartbeat and independent termination path; Vercel retains short HTTP handlers and console. Vercel documents [finite function durations](https://vercel.com/docs/functions/limitations); a background promise after webhook response is not a durable supervisor. A workflow's durable state is not itself a persistent socket. Host selection, availability, restart behavior and costs require approval. No hosting is provisioned.

Estimate, not commitment: 1–2 hours for initial contract/scaffold; approximately 1–2 engineering days for worker, durable binding and adversarial local testing after the remaining provider contracts are resolved. No real signature verifier exists in this slice.
