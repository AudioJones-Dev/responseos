# Grok local socket successor

EXPERIMENTAL, local synthetic validation only. This follows the frozen injected-bridge checkpoint 2f7e160705a501516471914f157ed0b48ce0dceb. The frozen Telnyx application/control pair and original commissioning baselines remain untouched.

`lib/grok/mediaServer.ts` composes a real Node HTTPS server with `ws` WSS ingress. It verifies the configured destination, unique signature/token headers and Ed25519 signature before upgrading, requires connected then exact start frames, bounds connection count/frame sizes/queued work, checks ping/pong health, and delegates durable consent/stream claims to the existing bridge. TLS certificates are required. It does not trust forwarded headers or derive the signed URL from a request. A trusted TLS termination/proxy deployment design remains an explicit hosting decision; this implementation terminates TLS directly.

`lib/grok/networkTransport.ts` constructs the actual pinned realtime WSS client and Telnyx HTTPS commands. It validates certificates, disables redirects and compression, limits payloads/timeouts, passes credentials only in headers, and has no retries. Carrier HTTP success is command acceptance only. The provider adapter now wires the exact consumed command ID into streaming_start; xAI SIP termination remains disabled. `scripts/grok-media-server.ts` is the production entry point, but the hard qualification gate runs before config/credential reads or socket creation. There is no environment activation bypass.

The explicit synthetic transport mode accepts only literal 127.0.0.1 HTTPS/WSS with an explicit test CA and a fixed synthetic bearer value. It cannot select external provider endpoints. Integration tests mock only the qualification/adapter boundary to route real TLS requests to these synthetic peers; they exercise real WebSocket upgrade/framing, model/config exchange, PCMU relay, exact operator hangup HTTP, signature rejection, replay, socket loss, oversized/binary input and withdrawal. This is materially stronger than injected socket methods, but it does not authenticate to Telnyx/xAI, demonstrate model reasoning, prove actual provider event shapes, or establish remote cancellation/billing cessation.

Dependencies: ws8.22.0 and @types/ws8.18.2 pinned with registry integrity; optional native acceleration is not installed. No lifecycle scripts run for these packages. Public package downloads are separate from external-provider testing; all test sockets run inside disposable network-none Docker namespaces. Existing Node24.18.0/npm11.16.0 and cached Postgres16/17/18 remain pinned. Deployment install/activation flags remain false.
