## Configuration and trust boundary

Direct TLS remains the default when ingress is omitted, with required certificate/private-key paths and the existing configured port. Explicit ingress `managed-edge-http` creates a Node HTTP listener using a strictly validated PORT (1024 through 65535); config port/certificate fields are rejected in that mode. Unknown ingress and missing/malformed PORT fail closed. This choice is separate from production qualification and local-synthetic transport selection. The production qualification assertion remains unchanged and always rejects, including before entrypoint config/certificate reads and before provider key access in transport constructors. Database module initialization is not claimed to occur after that gate.

Railway would terminate Telnyx TLS at its managed edge and forward plaintext HTTP/WebSocket traffic to Node within the hosting boundary. This is NOT end-to-end Telnyx-to-Node TLS. No simultaneous public TCP proxy is part of this design. Hosting topology, ingress isolation, edge log redaction, header preservation, timeouts and actual proxy behavior must be qualified before hosted use. The application cannot infer edge provenance from arbitrary forwarded headers. The service's backend must not be exposed as an alternative public ingress.

Signature authority remains the exact configured external WSS URL, including query string. The managed-edge URL must be canonical as represented by URL.href; the signed string itself is never rebuilt from request headers. Received raw path/query must match exactly; Host must match the configured external authority and occur once. Proxy Host rewriting is unsupported and fails closed. Forwarded and X-Forwarded headers confer no authority. All three authentication headers must occur once; duplicate, stale or invalid values fail before upgrade. A valid upgrade still needs the original single-use token, saved consent and exact stored call/session/capture/generation binding before xAI access. Outbound xAI TLS verification, endpoint restrictions, frame/queue limits, heartbeat, permanent-stop/withdrawal and shutdown logic remain unchanged.

Primary documentation inspected October 19: [Railway TCP proxy](https://docs.railway.com/networking/tcp-proxy) assigns an external port that remains necessary with a CNAME; selectable443 and Telnyx support for that assigned port are not established. [Railway managed TLS](https://docs.railway.com/guides/spa-routing-configuration) documents edge TLS termination. [Telnyx signature contract](https://developers.telnyx.com/docs/voice/programmable-voice/media-streaming) signs timestamp plus the exact configured stream URL. These documents are not proof of an actual deployed proxy's behavior.
