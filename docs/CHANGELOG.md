## Unreleased — v0.2 closeout step 2.4 PR 32B: Clerk session derivation + conservative role mapping

- **Wired** Clerk's server-side `auth()` into `lib/auth/session.ts` behind the **unchanged public contract** — same exports (`getCurrentSession`, `getCurrentUser`, `getCurrentAccount`, `requireRole`, `requireTenantScope`, `resolveTenantScope`), same types (`Session`, `SessionUser`, `SessionAccount`), and same error classes (`TenantScopeError`, `RoleDeniedError`, `DevSessionInProductionError`). No call site changed.
- **Dispatch order:** (1) production guard — `RESPONSEOS_DEV_SESSION` under `NODE_ENV=production` still throws `DevSessionInProductionError`; (2) explicit `RESPONSEOS_DEV_SESSION` override wins in non-production (the CI/test bypass, plan §4.7); (3) Clerk path when `CLERK_SECRET_KEY` is set; (4) placeholder fallback (defaults to `aj_admin`) preserved when Clerk env is absent. **Clerk env absent → existing dev/mock behavior is unchanged.**
- **No JIT provisioning (operator Q1).** The Clerk path resolves only existing rows: maps `userId → User.clerk_user_id` and active `orgId → Account.clerk_org_id`. An unauthenticated request, an unmapped user, or an active org with no mapped account all resolve to `null` through the existing unauthenticated pathway. No auto-create, no silent tenant guessing. Webhook-driven sync is 32C.
- **Conservative role mapping (operator Q4).** The DB `User.role` is the source of truth for the grant; Clerk's generic org membership role never widens privileges. `aj_admin` is granted only in the AJ Digital control-org context. In a client-tenant context `client_admin` requires an explicit DB grant and everything else caps at `client_viewer` — a DB `aj_admin` active in a client org resolves to `client_viewer`, never `aj_admin`.
- **Multi-org membership (operator Q15).** Active Clerk org first. Fallback to `AJ_DIGITAL_CLERK_ORG_ID` applies only for control context (no active org + control-plane DB user) and yields `Session.account = null`. When no active org can be resolved for a non-control user, the session resolves to `null` rather than guessing a tenant.
- **Tenant-binding guard (tenant isolation).** A tenant session is built only when the mapped `User.account_id` equals the account resolved from the active Clerk org. If a multi-org user's active Clerk org maps to a different account than their DB tenant, the session fails closed (`null`) instead of reusing the user's global role for a tenant they don't belong to — preventing cross-tenant privilege reuse.
- **No external/global cache (operator Q14).** Request-scoped caching was evaluated and deferred — not introduced. No Redis, process, or global cache.
