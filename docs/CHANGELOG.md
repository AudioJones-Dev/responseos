## Unreleased — ADR-0020: provider credential encryption (app-layer, env-managed key, opaque ciphertext) for v0.2 substrate

- **Added** ADR-0020 in `docs/DECISIONS.md` resolving Q1 of `docs/product/RESPONSEOS_V0_2_REMAINING_MODELS_IMPLEMENTATION_PLAN.md` and acting as the precondition for v0.2 closeout step 2.3 PR 31A (`provider_connections`). The decision: provider credentials are never stored in plaintext; v0.2 uses application-layer AES-256-GCM with a 12-byte random nonce, AAD bound to `(account_id, provider)`, and a single env-managed key contract (placeholder `RESPONSEOS_PROVIDER_KEY`). The encrypted artifact is stored as opaque `Bytes` (Postgres `bytea`) with a fixed-size envelope header `[version | algorithm | nonce]` prepended to the ciphertext; no queryable JSON secrets, no indexing on credential contents. When the key env var is absent, the encryption module falls back to a redacted-sentinel placeholder per ADR-0001 — the app boots and runs with zero credentials.
- **Explicitly deferred** to future ADRs: KMS / Vault / live secret-manager integration, per-tenant key isolation (HIPAA-ready lane per ADR-0004), key-rotation runbook, live provider wiring, and break-glass decryption audit (which integrates with `audit_logs.category = "break_glass"` once 31D ships per the §31D plan).
- **Updated** the Q1 row in `docs/product/RESPONSEOS_V0_2_REMAINING_MODELS_IMPLEMENTATION_PLAN.md` to point at ADR-0020 as the resolution.
- **Scope checklist:** docs-only ADR. No `prisma/schema.prisma` changes, no migrations, no generated Prisma client changes, no runtime crypto implementation, no `provider_connections` model code, no seed/test/runtime changes, no auth work, no deploy work, no UI work, no KMS/Vault integration, no live Twilio/HubSpot/n8n/provider wiring.
- 31A may now implement schema and data-layer contracts against this posture (a `credentials_encrypted Bytes` column, an `oauth_refresh_token_encrypted Bytes?` column where applicable, and a `lib/providers/encryption/*` round-trip module with mock fallback). The encryption module ships in 31A; this ADR specifies *what* it must do.
- Per ADR-0019 step 2.3 (precondition). Tracks roadmap checkpoint issue #27.
