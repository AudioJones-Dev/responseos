# ResponseOS — Demo Deploy Runbook

**Status:** Active. First production-bound deploy of v0.2.
**Audience:** Operator with admin access to Vercel + Neon + the GitHub repo.
**Time budget:** ~60 minutes end-to-end (most of it waiting on first build).

This runbook ships ResponseOS v0.2 to a Vercel `*.vercel.app` URL backed by a Neon Postgres seeded with deterministic demo data, gated by HTTP basic auth at the edge. **Real auth (Auth.js), real provider integrations (Twilio/Retell/Vapi/Stripe/Resend/GHL/HubSpot), and the rest of the v0.5 commercial motion remain deferred.**

What this gives you:
- A live, password-protected URL clients can visit.
- Marketing pages, admin dashboards, and client dashboards all rendering against real Postgres rows that match `lib/mock/*` exactly.
- All 50 routes working, including the 24 API routes (`/api/*`) returning the canonical envelope.

What this does **not** give you:
- Real users (everyone behind basic auth becomes `aj_admin`).
- Real provider data (no Twilio webhooks, no Stripe customers, no Retell calls — the seed is the only data).
- Real billing or outcome-fee math (v0.5).

---

## 1. Provision Neon

1. Go to [console.neon.tech](https://console.neon.tech) → **Create project**.
2. Project name: `responseos-demo`. Postgres version: **16**. Region: closest to where the demo will be shown.
3. Once provisioned, the dashboard shows two connection strings:
   - **Pooled** (`...pooler.neon.tech`) → this is the one for `DATABASE_URL`.
   - **Direct** (`...neon.tech` without `-pooler`) → this is the one for `DIRECT_URL`. Open Connection Details → switch the toggle to "Direct".
4. Save both. Don't put them anywhere except your password manager and Vercel.

## 2. Run migrations and seed the database

From your local checkout of `master`:

```bash
DATABASE_URL='<Neon pooled url>' \
DIRECT_URL='<Neon direct url>' \
npx prisma migrate deploy

DATABASE_URL='<Neon pooled url>' \
DIRECT_URL='<Neon direct url>' \
npx prisma db seed
```

The seed is idempotent (Phase A acceptance criterion in `docs/v0.2-implementation-spec.md` §10). Re-running is safe.

Sanity check: connect with `psql "$DIRECT_URL"` and run `SELECT COUNT(*) FROM "Organization";` — expect 2. `SELECT COUNT(*) FROM "Contact";` — expect 3.

## 3. Hook the repo to Vercel

1. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → select `AudioJones-Dev/responseos`.
2. **Framework preset:** Next.js (auto-detected).
3. **Build command:** leave default (`next build`).
4. **Output directory:** leave default.
5. **Install command:** leave default (`npm ci`). The `@prisma/client` postinstall handles `prisma generate`.

## 4. Add environment variables in Vercel

Project → Settings → Environment Variables. Add for **Production** AND **Preview**:

| Name              | Value                                              |
|-------------------|----------------------------------------------------|
| `DATABASE_URL`    | Neon pooled URL (`...pooler.neon.tech`)            |
| `DIRECT_URL`      | Neon direct URL (`...neon.tech` without `pooler`)  |
| `NODE_ENV`        | `production`                                       |
| `BASIC_AUTH_USER` | pick one (e.g. `demo`)                             |
| `BASIC_AUTH_PASS` | strong random string (e.g. `openssl rand -hex 16`) |

**Do not set `RESPONSEOS_DEV_SESSION` in production** — `lib/auth/session.ts` throws `DevSessionInProductionError` if it's set with `NODE_ENV=production`. Leaving it unset makes every authenticated viewer the default `aj_admin` session, which is exactly what we want for a demo.

## 5. Trigger the first deploy

Vercel deploys automatically on the first import. The first build takes ~3 minutes. Watch the build logs for:

- `prisma generate` (postinstall) — should succeed, regenerating client.
- `next build` — expect 50 routes, no errors.
- `Collecting page data using N workers` — this is when prerendered pages call `lib/data/*` against Neon. If Neon is slow or migrations weren't run, this is where it fails.

When the build succeeds, the URL is `https://<project-slug>.vercel.app`. Open it. You should be prompted for HTTP basic auth. Enter the `BASIC_AUTH_USER` / `BASIC_AUTH_PASS` you set. After auth, the marketing home page loads, then `/admin` shows the AJ admin dashboard with seeded data, and `/client/dashboard` shows the Sunshine HVAC client view.

## 6. Smoke checklist

Hit each of these and confirm seeded data renders:

- [ ] `/` — marketing home loads.
- [ ] `/pricing` — pricing page loads.
- [ ] `/admin` — AJ admin dashboard renders, organization list non-empty.
- [ ] `/admin/leads` — lead list shows seeded leads (`lead_mock_1` through `lead_mock_11`).
- [ ] `/admin/calls` — call list shows seeded calls.
- [ ] `/admin/reports` — revenue metrics chart renders.
- [ ] `/client/dashboard` — Sunshine HVAC client dashboard renders.
- [ ] `/api/health` — returns `200` **without** basic auth (PUBLIC_PATHS in `proxy.ts`).
- [ ] `/api/leads` (with basic auth) — returns `{ ok: true, data: [...] }` envelope.

## 8. Rollback

The deploy itself is fully reversible:

- **Code rollback** — Vercel → Deployments → previous deployment → "Promote to Production". Takes ~10 seconds.
- **Auth gate kill switch** — unset `BASIC_AUTH_USER` and `BASIC_AUTH_PASS` in Vercel; the proxy falls through (the gate is opt-in by env var presence). Use this if basic auth is blocking a real client mid-demo.
- **DB nuke + re-seed** — connect to Neon, run `prisma migrate reset --force`, then `prisma db seed` again. Idempotent; safe in dev/demo, never run in real production.

The deploy is non-destructive to existing repo state — the only commits going to master are this PR's two files (`proxy.ts`, `.env.example` update) plus this runbook.
